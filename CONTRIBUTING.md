# Contributing

Thanks for considering a contribution.

## Before opening a pull request

1. Open an issue describing the problem or proposed change.
2. Keep changes focused and explain user impact.
3. Include tests for behavior changes.
4. Update documentation when contracts or workflows change.
5. Do not include credentials, private logs, or personal data.

## Local development

```bash
npm install
npm run dev
npm run build
```

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] The production build succeeds.
- [ ] UI states are usable on narrow screens.
- [ ] Security implications are documented.
- [ ] Documentation and roadmap are updated where relevant.
